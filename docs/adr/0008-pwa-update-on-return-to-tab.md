# ADR 0008: PWA の新しい版は、タブが非表示から表示に戻ったときに自動で入れ替える

## 背景

ADR 0007 は、新しい版を古い画面がすべて閉じた次回の起動で有効にすると決めた。読み込み途中で版が混ざらない代わりに、放置ゲームのように画面を開きっぱなしにする人には、公開した更新が何日も届かない（#21）。#21 では、更新を知らせる画面を出す案と、画面に何も出さず戻ったときに入れ替える案を比べ、リポジトリのオーナーが後者（案 B）に決めた。決定 #8（画面に操作ボタンを増やさない。ADR 0006）と合わせるため、通知の画面は置かない。

## 決定

- `src/pwa/register.ts` が `register()` の戻りの registration を見る。タブが非表示から表示に戻ったとき、`registration.waiting` があれば `{ type: "SKIP_WAITING" }` を送って有効にする。
- 有効になったら `location.reload()` を 1 回だけ呼ぶ。有効になったことは、`controllerchange` と待機中のワーカーの `statechange`（`activated`）のどちらか先に来た方で判断する。
- 待機中の版が無いとき、表示のまま版が届いたときは何もしない。送信が失敗しても例外を出さず、再読み込みもしない（次に戻ったときにもう一度試す）。
- `vite.config.ts` の `skipWaiting: false` / `clientsClaim: false` は変えない。ADR 0007 のうち、この 2 つの設定と、更新の通知 UI を置かない方針は引き続き有効。置き換えるのは「次回起動まで入れ替えない」の部分。
- 非表示になる時点でゲームは保存済み（既存の挙動）なので、再読み込み後は保存から続きが始まる。買収提案の返事待ちも保存から同じ状態で再開する。

## 捨てた案

- **更新を知らせる画面を出し、押したら再読み込みする**: 操作が 1 つ増える。決定 #8 に反する。
- **`skipWaiting` と `clientsClaim` を有効にする**: 開いている画面の版が途中で切り替わり、古い画面が新しい版の資産と混ざる。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 入れ替えの契機。非表示から表示に戻ったとき以外（一定時間の経過など）を足してもよい。
- **壊すと危ない**:
  - 入れ替えは画面が見えていない状態から戻った瞬間だけにする。表示中に入れ替えると、遊んでいる最中に画面が切り替わる。
  - 再読み込みは 1 回だけにする。有効にしても待機中の版が残る作りになると、戻るたびに再読み込みが続く。
  - `SKIP_WAITING` の受信処理は workbox が `skipWaiting: false` のときに `sw.js` へ入れる。workbox の設定を変えたら、ビルドした `sw.js` に残っているか確認する。
  - Chromium で確かめたところ、`clientsClaim: false` のままでも、既存のタブに `activating`、`controllerchange`、`activated` の順でイベントが来た。ほかのブラウザでは確かめていないため、待機中のワーカーの `statechange` も待っている。片方だけに寄せない。
  - 保存は、新しい版が古い版の保存を読めること（ADR 0002）。入れ替えのたびに保存から再開するため、この前提が崩れると町を失う。
