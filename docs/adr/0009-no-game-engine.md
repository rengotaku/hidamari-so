# ADR 0009: ゲームエンジンと物語用のツールを使わない

## 背景

技術構成を決めたとき（親 #1 の Decision Log #2）は雛形（my-boilerplate の `react-spa-cloudflare`）を選んだだけで、ゲームエンジンや物語用のツールと比べた記録が無い。その後、#64（ちゃぶ台が住人より手前に描かれる）と #68（15 倍で住人が横に滑る）を直したところで、「既存の仕組みを流用できなかったか」と問われた。

今の作りは次のとおり（テストを除いて約 8,500 行）。

- 描画: 人・家具・空・町を Canvas 2D に 1 ドットずつ四角で塗る（`src/render/`）。画像ファイルは使わない
- 動き・時間: ゲーム内時間の刻み（ADR 0004）、歩く経路、描く位置の追従（`src/render/smooth.ts`）
- 出来事: 条件・重み・cooldown・予約で出来事を選ぶ仕組みと、言い回しの差し込み（`src/sim/storylets.ts`、ADR 0001）
- 画面: React、保存は localStorage、公開は Cloudflare Pages と PWA

## 決定

- 描画を PixiJS や Phaser へ移さない。Canvas 2D に四角を塗る自作の描画を続ける
- 出来事を選ぶ仕組みも自作のままにする。ink・Yarn Spinner・Tracery は使わない

## 理由

今回直した不具合を、既存の仕組みで避けられたかどうかで突き合わせた。下の見立ては、各ツールが一般に持つ機能から判断したもので、このゲームに組み込んで試してはいない。

| 不具合 | 候補 | 避けられたか |
|---|---|---|
| #64 ちゃぶ台が住人より手前に描かれる | PixiJS・Phaser（奥行きの値で描く順番を決める機能がある） | 避けられた可能性が高い。描く順番を手で並べていたのが原因だった |
| #68 15 倍で住人が滑る | 同上（位置をなめらかに動かす機能がある） | 半分だけ。なめらかに動かすことはできるが、「時間は 15 倍、歩きは 1 倍」が両立しない問題はゲームの作りの側に残る |
| #68 吹き出しと当たり判定が描く位置からずれる | 同上（表示している物の位置で当たり判定をする） | 避けられた可能性が高い |
| 吹き出し同士の重なり | 決まった解決策を持つエンジンは見当たらない | 避けられない |
| #44 恋の出来事の頻度、闇金の筋のテスト | ink・Yarn Spinner（会話の分岐を書くためのツール） | 避けられない。条件と重みで出来事を選ぶ形は、これらの対象外 |

エンジンで楽になるのは、描く順番・なめらかな移動・当たり判定の 3 つ。どれも今は直してある。一方、移すと次の手間がかかる。

- 絵を画像ではなくコードで塗っているので、エンジンに移すには `src/render/` の描画をほぼすべて書き直すことになる。画像にするなら、絵をすべて描き起こすことになる
- 困っている不具合の多く（出来事の頻度、テストのシード依存、吹き出しの重なり）は、エンジンを替えても残る

物語用のツールは、選んだ道筋どおりに会話を進めるためのもので、「住人の状態と時刻から、起きうる出来事を重みで 1 つ選ぶ」このゲームの形には合わない。言い回しの組み立て（Tracery）は置き換えられるが、困っていた点ではない。

## 捨てた案

- **描画を PixiJS へ移す**: 描く順番と当たり判定は楽になるが、描画の書き直しに見合わない
- **描画を Phaser へ移す**: 上に加えて、ゲームループ・時間の管理もエンジンに合わせることになり、ADR 0004 の時間の進め方（tick と step、留守中の進行）を作り直すことになる
- **出来事を ink や Yarn Spinner で書く**: 上記のとおり形が合わない

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 絵を画像（スプライト）で描くと決めた場合は、この ADR を見直す。そのときはエンジンを使う利点が大きくなる。描画の量が増えて、描く順番や当たり判定の不具合が続くようなら、それも見直す合図になる
- **壊すと危ない**:
  - 描く順番は、`src/render/room.ts` などの呼び出しの順番で決まる。家具や人を足すときは、奥にある物を先に描く（#64）
  - 描く位置はゲームの中の位置と別に持っている（`src/render/smooth.ts`、#68）。新しく動く物を足したら、描画・吹き出し・当たり判定のすべてで描く位置を使う
  - 新しい層（音、パーティクルなど）でライブラリを使うかどうかは、層ごとに比べて新しい ADR に残す。比べずに決めると、この ADR を書くことになった状況を繰り返す
