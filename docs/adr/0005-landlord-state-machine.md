# ADR 0005: 入居は大家の状態機械に一本化する

## 背景

元の要望は「退去者とか出ると、大家が部屋をリセットして、入居者を連れてきたり、入居者がくると自分の部屋にもようがえする」（#4）。プレイヤーは大家を操作しない（親 #1 Decision Log #8）ので、大家は画面の中の登場人物として自動で動く（Decision Log #10）。事前設計テスト F5 は、「片付けの途中で次の入居が決まっても、片付けが終わってから入居の場面になる（前の住人の装飾が新しい住人の部屋に残らない）」を要求している。

## 決定

新しい住人が入る経路は 1 つだけにした。ゲーム開始時の初期住人（`newGame`）を除き、`moveIn`（`src/sim/init.ts`）は大家の `welcome`（`src/sim/landlord.ts`）からしか呼ばれない。

1. **退去**: 出来事の効果 `moveOut`、または同棲で部屋を移る `cohabit` が、部屋を空室にして「片付け待ち」（`vacancies`）を積む。入居の日は 2〜4 日後に抽選で決める（`openVacancy`）。同棲の相手が残る部屋は空室にならない。
2. **片付け**: 大家が手すきのとき（日中の 8〜19 時）、片付け待ちの部屋に向かう。戸口に着いて 90 分かけて片付けると、部屋の装飾が空になり、窓に募集の貼り紙が出る（`room-cleared`）。
3. **連れて来る**: 片付けが済み、入居の日が来た部屋にだけ、新しい住人を入れる。大家が新しい住人を連れて階段を上がる。住人の種類は抽選するが、人生の筋の途中でだけなる種類（`arc-only`）は除く。
4. **入居と模様替え**: 部屋に着いたときに初めて `moveIn` が住人の表へ入れる。部屋には段ボールだけを置き、ゲーム内 1 日（`SETTLE_MIN`）かけて、住人の装飾のセット（`decorPlan`）を 1 つずつ置き、段ボールを減らす（`settleDecor`）。そろったら `room-settled` を日誌に書く。入居の日誌 `room-move-in`（歓迎会の予約を含む）も、この時点の 1 回だけ。

大家の状態（`phase`: idle / up / clearing / escort / down、位置、連れている住人）は `GameState.landlord` に持ち、保存される。

## 捨てた案

- **退去と同時に次の住人を入れる**: 前の住人の装飾が残る、または消すタイミングを別に作ることになる。大家の片付けという見せ場（要望）も無くなる。
- **入居と同時に装飾を全部置く**: 模様替えの過程を見せたい要望に反する（#4 の「やってはいけないこと」）。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 入居までの日数（`MOVE_IN_DELAY`）、片付けの時間（`CLEAR_MIN`）、模様替えの時間（`SETTLE_MIN`）、大家が動く時間帯（`WORK_HOURS`）、歩く速さ。
- **壊すと危ない**:
  - 新しい住人を別の経路（出来事の効果など）から入れない。片付け前の入居や、装飾の残りが起きる。`moveIn` の呼び出し元が 2 つ（初期住人と大家）だけであることが前提（コードで確認済み。これを検査するテストは無い）。
  - 大家は同時に 1 つの仕事しかしない。`startJob` は、片付け待ちの部屋を先に、次に入居の日が来た部屋を見る。複数の仕事を並行させる場合は、`landlord` の状態（単一の `phase` と `room`）を作り直す必要がある。
  - 大家が連れている住人（`escort`）は、住人の表（`res`）にまだ入っていない。`res` を走査する処理（行動、抽選、描画）に入る前の住人を混ぜない。
  - 昼間の時間帯（8〜19 時）にしか動かないため、空き部屋は夜の間は片付かない。時間帯を変えると、入居の日誌の時間帯も変わる。
