# ADR 0006: 画面に数値と操作ボタンを出さない

## 背景

元の要望は「攻略したいわけではなく、日常をみたい」「UIはスクロールなしがいい」「シンプルなUI。だけど深みのある操作」「パラメーターは持っていてもいいがユーザには見せなくて良い。ユーザは、キャラをみるのと、日誌くらい」（親 #1、#4 の元の要望）。数値を最適化させる見せ方は、眺めるゲームに合わない。

## 決定

- 画面に出すのは、建物の様子（住人の動き）、住人を押すと出るプロフィール、日誌の 3 つ。スクロールしない 1 画面にする（親 #1 Decision Log #6、#7）。
- 気分・所持金・評判などの数値は内部にだけ持つ。プロフィールに出すのは、名前・年齢・職業・「いま」の行動・だめなところ（癖の名前と説明）で、すべて言葉（`src/ui/Profile.tsx`、`src/ui/text.ts`）。`src/ui/GameScreen.test.tsx` が、初期表示・日誌・プロフィールに数値が出ていないことを検査する。
- 画面上部は日付・時刻と築年数だけ。天気は絵で分かるので文字で出さない（Decision Log #9）。
- 大家（プレイヤー）の操作は無くす。家賃・設備・入居者はゲームが自動で決める。**プレイヤーが選ぶのは、築 50 年の記念日の買収提案（売る / 断る）だけ**（Decision Log #1、#8）。ダイアログは `src/ui/BuyoutDialog.tsx`。売れば結末で、以後は進まない。断れば続き、記念日は二度と来ない。
- **時間の速さのボタン（停止 / 1 / 4 / 15 倍）は、眺める側の操作として別枠で置く**（Decision Log #15、sub-issue #14）。当初は「置かない」としていたが、利用者の要望で取り消した。ゲームの内容に影響する選択ではなく、眺める速さを変えるだけなので、#8 の「プレイヤーが選ぶのは買収提案だけ」とは別の扱いにする。買収提案の場面では自動で停止する（ADR 0004）。
- 部屋や住人を押して見る操作（大写し、プロフィール、日誌の名前から出ていった住人の記録を開く）は、状態を変えない閲覧の操作として許す。

## 捨てた案

- **気分や所持金をバーや数字で見せる**: 攻略や最適化の遊び方に寄る。「日常をみたい」に反する。
- **大家としての操作（家賃、設備、入居者の選択）を残す**: 眺める体験より管理の体験が前に出る。
- **速さのボタンを置かない**: 利用者から「時間の流れの高速化の機能は復活してほしい」という要望があり、取り消した（#14）。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 速さの種類と見た目（ADR 0004）、プロフィールに出す言葉の文面、日誌の見せ方、買収提案の文面。
- **壊すと危ない**:
  - 内部の数値を画面に出さない。出すと、数値を上げ下げする攻略の遊び方が生まれる。`GameScreen.test.tsx` が外れたら、意図した変更か確認する。
  - 操作を足すときは、「ゲームの内容に影響する選択」か「眺める側の操作」かを先に決める。前者を足すのは Decision Log #8 を変える判断なので、新しい ADR で決定を覆す（この ADR に `superseded_by` を付ける）。
  - スクロールしない 1 画面を保つ（スマホ幅でも 4 つの速さボタンが収まる）。ヘッダーに項目を足すと崩れやすい（未確認: 実機での幅は、この文書を書く時点で再確認していない）。
  - 買収提案の「売る」の結末は以後進まない（`isEnded`）。開き直すと新しいゲームになる（`loadOrNew`）。
